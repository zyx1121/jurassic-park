# CLAUDE.md

Unity 6000.3 LTS, URP, C#. Co-op RTS survival game rebuilding the Warcraft III "Jurassic Park" 6.3 map, for the NYCU 3D Game Programming course (Fall 2026). Solo project.

`docs/PLAN.md` is the single design source of truth (v1, 2026-09-17). `docs/ART_DIRECTION.md` owns visuals. `main` was reset on 2026-09-17; the old prototype is on the `legacy` branch for reference only. Do not copy code back from `legacy` wholesale.

## Rules

- Follow the plan. Anything marked confirmed in PLAN section 1 is settled; content and numbers come from the original 6.3 map (`docs/ORIGINAL_CONTENT.md`), not invention. Raise a decision instead of improvising when the plan is silent.
- Simulation is pure C# with no MonoBehaviour dependency. Every input (player, GUI, AI seat) goes through Command, Task, Plan, Action. Rendering, animation and GUI never mutate simulation state.
- Host-authoritative. Clients send commands and render snapshots; no client prediction or lockstep. Single player is the same path with nobody connected. Netcode for GameObjects is used for the connection and named messages only (`NetMessages`): no NetworkObjects, no NetworkBehaviours, no scene management. The seat a command speaks for comes from `SeatBinder`, never from the payload.
- Presentation reads `MatchReadModel` (snapshots) and sends through `GameSession.Commands`. It never touches `SimulationRuntime`, so the same code runs on a host and on a client that has no simulation.
- Every gameplay number lives in a ScriptableObject under `Assets/Data/`, not a literal in code.
- Scripts live in `Assets/Scripts/<System>/`, namespace `JurassicPark.<System>`. One MonoBehaviour, ScriptableObject or NetworkBehaviour per file, file name equals class name, or builds lose the script reference.
- Never hand-edit `.unity`, `.prefab` or `.asset` YAML while an Editor is open. Scenes and prefabs are generated by builder commands; change the builder, rerun, commit the result.
- Unity automation goes through the Unity CLI (`unity run`, `unity test`, `unity build`); read the unity-cli skill references first. Unity runs on the MacBook (owner's decision, 2026-09-17): tests, the resident Editor, Play checks, captures and builds. The game targets a MacBook Air M2 at 60 fps: one terrain mesh, instanced materials, no per-frame allocations in views, and a low frame rate for batch-mode Editors so the fanless machine does not throttle.
- New files under `Assets/` need their `.meta` committed. Binary assets go through Git LFS. Sprites are point filtered, no compression, no mipmaps.
- Verify before claiming done: `tools/test.sh` must show zero failures from a fresh report, or a real build or Play Mode check. CI only checks repo hygiene.
- Work is tracked as GitHub issues under milestones M0 to M6. Branch, PR, CI green, squash-merge. English commit messages, imperative mood.
